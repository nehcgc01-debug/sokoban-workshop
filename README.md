推箱工坊 · Sokoban Workshop

一个以温暖工坊为主题的 Godot 推箱子游戏原型。玩家将木箱推到目标点；部分关卡允许使用一次牵引，决定何时使用这次机会。项目包含七个示例关卡和可保存、读取、试玩的关卡编辑器。

运行方式
1. 下载仓库完整源码与资源。
2. 使用 Godot 4.6 标准版，在项目管理器中导入根目录的 project.godot。
3. 打开项目后按 F5，在主菜单选择“开始游戏”或“关卡编辑器”。
游戏操作
- 方向键或 WASD：移动、推动箱子。
- Shift + 方向键：在启用牵引的关卡中后退，并把身后的箱子拉入原站位。每关可用一次；按住 Shift 可预览牵引。
- Z：撤销一步；R：重开当前关卡。
- H：在第 6、7 关逐级查看提示。
- B：内置关卡进入无解状态时，回到此前可解的局面。
- M：切换音效；Esc：返回。
- 所有箱子到达目标点后通关。
关卡编辑器

使用鼠标放置或擦除，数字键 1–5 选择墙、擦除、目标、箱子和玩家起点；也可以点击工具按钮。S 保存、L 读取、T 试玩，Esc 返回。支持三个自定义存档槽，以及为自定义关卡启用一次牵引。

试玩要求玩家起点、箱子和目标等满足基础结构检查。通过结构检查不代表关卡一定可解。 内置七关支持精确死局判断；自定义关卡使用较保守的角落死局提醒，不覆盖所有无解情形。

设计思路

本作尝试把牵引作为有限资源：玩家需要选择何时使用它，而不只是判断如何推动箱子。第 4 关引入牵引，第 5–7 关逐步探索牵引的使用对象与时机。牵引不是本项目首创机制，本作的重点是其限制与关卡设计的结合。

制作与 AI 辅助说明

本项目基于我早期在指导下搭建和测试的 Godot 推箱子原型。我提出了游戏方向、工坊氛围和角色视觉需求，并参与原型搭建、测试与迭代决策。

项目后续的代码、界面、素材整合、测试和部分设计使用了 AI 辅助。Claude 参与试玩评审，通过程序生成与筛选提供了第 6、7 关，并协助后续版本改进；这些关卡另经过求解和流程验证。角色图由 OpenAI 根据我提供的角色概念生成。素材和第三方组件的来源、许可见项目内相关说明，包括 art/ 和 fonts/ 中的文件。本项目并非全部由本人独立手写。

测试与已知限制
- 从 GitHub 仓库下载的 V7.8 源码在 Godot 4.6.3 下成功导入；307 项自动断言与七关求解通过。
- 早期 V7.6 的网页构建做过浏览器操作测试；不能将该结果视为 V7.8 的网页验收。
- V7.8 尚未完成 Windows 原生运行、声音及连续动画流畅度的验证，也尚无独立真人玩家测试。
- 自定义关卡没有通用的一键可解性验证；错误的存档不会自动从备份恢复。
- 这是一个小型游戏原型，不宣称已达到成熟商业产品的完整质量。
项目结构
- project.godot：Godot 项目入口。
- main_menu.gd / .tscn：主菜单和关卡选择。
- game.gd / .tscn：游戏规则和游玩界面。
- level_editor.gd / .tscn：关卡编辑器。
- levels/：示例关卡和原始地图。
- art/、`fonts/`：美术、字体及相关说明。
- tests/：自动测试。
