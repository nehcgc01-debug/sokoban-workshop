# 推箱工坊 · Kuro Sokoban

一个固定 7×6 网格的推箱子原型，包含独立主菜单、七个可游玩的示例关卡、三槽自定义关卡存档，以及可以试玩并返回继续编辑的内置关卡编辑器。

## 最快运行

1. 使用 **Godot 4.6.x 标准版（无需 .NET）**。本次自动测试使用 Godot 4.6.3；原项目来自 4.6.stable。
2. 将整个文件夹解压到一个新位置，不要直接覆盖自己正在编辑的旧工程。
3. 在 Godot 项目管理器中导入本目录的 `project.godot`，打开后按 **F5**。
4. 主菜单 → 进入工坊 → 选择示例关卡。首次运行不需要任何外部存档。

使用 Compatibility 渲染和 1152×720 基准画布。窗口缩放使用 canvas_items。中文字体已包含，不依赖评审电脑安装字体。

## 操作

### 游玩
- Tab：切换操作按钮；Enter / Space 激活聚焦按钮。通关时默认聚焦继续按钮，可按 Enter / Space 或 N 继续；最后一关返回主菜单。
- 方向键 / WASD：移动和推箱子；角色转向并平滑迈步，推拉带倾身和汗滴反馈。
- Shift + 方向键：在启用牵引的关卡中后退并拉动身后的箱子，每关一次。撤销返还次数，重开重置。
- Z / 撤销按钮：撤销一步，包括箱子位置、步数及通关状态。
- M / 音效按钮：静音或恢复原创合成音效；同一次运行内跨场景保持，重启程序默认开启。
- R / 重开按钮：重置当前选中的关卡，不切换存档。
- Esc / 返回按钮：普通游玩返回主菜单，编辑器试玩返回编辑器。
- 所有箱子都处于目标点上时通关。墙与边界阻挡玩家和箱子；不能连续推两个箱子。

### 编辑器
- 左键放置，右键擦除。
- 1 墙；2 擦除；3 目标；4 箱子；5 玩家起点。也可点击可见工具按钮。
- S 保存；L 读取；T 试玩；Esc 返回。保存、读取必须先明确选择槽位。
- 已有存档需要二次覆盖确认；上次内容备份为同路径 `.bak`。
- 勾选“启用一次牵引”可为自定义关卡配置一次拉箱机会；旧存档默认不启用。
- 草稿允许缺少玩家、箱子或目标，但试玩必须满足基础结构检查：合法坐标、一个玩家、至少一个箱子、箱子和目标数量相等、没有非法重叠。
- 基础检查不保证关卡可解。试玩后返回会恢复原草稿，游玩不会改变设计或存档。
- 读取、新建、返回主菜单有确认，防止误丢未保存改动。

## 原始地图与存档

原上传的两份地图原样保存在 `levels/user_custom_level.json` 和 `levels/user_custom_level_2.json`。在编辑器点“导入原始关卡”可作为未保存副本导入；没有自动覆盖已有用户存档。

两个原始地图通过结构检查，但对当前标准推箱规则的完整可达状态搜索未找到解（分别 1332、31 个状态）。因此保留作为原始设计记录，不把它们当作保证可通关的示例。

前3个示例训练单箱推动、多箱站位和转向留路；第4关明确演示一次牵引；第5关为18步资源决策谜题，要把唯一一次牵引用在正确箱子上。第6、7关分别考察保留牵引与使用时机。七关均经过求解器与实际逻辑验证。

三个自定义槽沿用原文件名：
- `user://custom_level.json`
- `user://custom_level_2.json`
- `user://custom_level_3.json`

`user://` 在工程文件夹之外。Windows 默认位置通常是 `%APPDATA%/Godot/app_userdata/Kuro_sukobann/`，可在 Godot 的 Project → Open User Data Folder 打开。发布源码时不会自动包含本机这些存档；本项目另有只读内置示例保障首次运行。

如主存档损坏，游戏会报错而不会自动读取备份。恢复前请退出游戏，先保留损坏文件副本，再将同目录对应的 `.bak` 文件复制为原文件名（例如 `custom_level.json.bak` → `custom_level.json`），重新启动后读取该槽。备份是上次覆盖前的内容，可能比当前进度旧。

## 文件结构

- `main_menu.gd/.tscn`：主菜单、示例及自定义槽选择、空槽与错误提示。
- `game.gd/.tscn`：移动、推箱、撤销、重开、胜利、下一关与试玩返回。
- `level_editor.gd/.tscn`：工具、草稿、保存/读取、覆盖与放弃确认。
- `game_state.gd`：跨场景选择及编辑器快照（Autoload）。
- `level_store.gd`：统一 JSON 解析、结构检查、存档路径、临时文件及备份写入。
- `progress_store.gd`：示例最佳步数持久保存。
- `board_view.gd`：共享网格绘制与可选贴图。
- `levels/`：七个可解示例及两份未改动的原始地图。
- `tests/`：可重复的逻辑、存储与场景导航测试。

## 美术与替换

已包含用户角色概念衍生的 AI 角色图与方向姿态、原创 SVG 木箱/地板/墙，来源见 `art/CHARACTER_CREDIT.md` 和 `art/ART_DIRECTION.md`。动作是静态方向图加程序插值，不是手绘逐帧。

替换角色正面可使用透明 `art/player.png`，保持竖向比例并重新导入。左右/背面来自 `player_directions.png`，其裁切区域在 `board_view.gd` 中，换图集时要同步调整。地块加载优先同名SVG，后备PNG；替换箱子、墙或地板时请一并处理已有SVG，避免只换PNG却看不到变化。修改后重新检查80px游戏格中的辨识度。

## V7.4 辅助体验

第6、7关为挑战篇。H或提示按钮可主动查看三层渐进提示；同一次进入关卡中R重开保留已查看的层级，返回菜单再进入会重置。编辑器试玩不显示内置关提示。

非目标箱子在固定墙/边界直角角落且牵引已经用尽时，给出可撤销的死角提醒。此检查刻意保守，不是完整无解检测；没有提醒不代表当前局面可解。

## V7.5 三项反馈修复

死角警告显示时，H不会消耗提示层级，提示按钮会说明先撤销。编辑器试玩若起点本来卡角，则提示返回编辑器修改，而不是推荐无效重开。选关保留暖色工坊背景和立绘，以半透明遮罩压暗，只隐藏重叠文字菜单。没有引入精确求解器或新机制。

## V7.6 轻量工坊情境

主菜单以“把木箱送回金色光圈”表达目标，操作名称仍保留关卡、编辑器等清楚字样。最后一关完成后，可以按E或点击“设计自己的关卡”进入真实编辑器；已有未保存草稿会保留。Enter/N仍返回主菜单。没有新增机制或修改存档格式。
